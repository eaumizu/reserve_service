# LINE連携完了時の予約通知

0014_line_booking_notifications.sqlをSupabaseの新しいクエリで実行してください。LINE DevelopersでWebhookの利用とWebhookの再送を有効にします。URLと認証情報の変更は不要です。通知のリンクはVercelのVERCEL_PROJECT_PRODUCTION_URLを使います。別ホストの場合はLINE_BOOKING_SITE_URLにHTTPSの本番オリジンを設定します（パスなし）。

新しく予約とのLINE連携コードを送信した時に、予約日時（日本時間）、メニュー、担当者、予約確認・変更・キャンセル用リンクを送ります。既存の専用リンクを使い続けるため、保存済みリンクは無効になりません。LINE連携前の予約に勝手に通知したり、以前連携した予約に一括送信したりしません。

送信待ち情報をDBへ保存し、連携とキュー登録は同じトランザクションです。専用リンクのトークンは店舗ごとの暗号化で保存し、LINE APIに受理された後で暗号化トークンを削除します。リトライキーは送信待ち情報ごとに固定し、受理済み409を成功として扱います。23時間を過ぎた送信待ちは再送せず、予約リンクの再発行で無効になった送信待ちも取り消します。

通信エラーやLINE APIの失敗時にはWebhookに503を返し、LINEのWebhook再送で同じキューを再処理します。同じコードを同じ本人のトークから再送しても復旧を試みます。定期的なバックグラウンド再送・予約変更通知・リマインドは今回は含みません。ブロック等によりLINEが受理しても届かない場合があります。

テストは新しいテスト予約で行ってください。連携コードを送るとLINEに日時とリンクが届きます。リンクを開き、同じ予約を表示できることを確認します。コードを再送して重複通知が来ないことも確認してください。予約変更・キャンセル操作は実データを更新するため、テスト予約のみを使用します。
