# 予約はメール必須・電話番号任意

0026まで適用済みの環境で、`0027_required_booking_email.sql` をSupabase SQL Editorで実行します。最新の公開先 https://reserve-service-beryl.vercel.app/ を使用してください。

お客様用Web予約と管理画面の手動予約で、メールアドレスを必須、電話番号を任意にします。入力された電話番号は書式と長さを確認し、全角数字を正規化します。空欄は空文字として保存し、架空の番号で補いません。確認画面と店舗通知は未入力の電話番号を適切に表示し、店舗通知にはメールアドレスも記載します。予約・変更・キャンセル・前日通知は従来の配信設定と再送機能を使います。

顧客台帳では、電話番号がある場合は従来の電話番号と氏名による照合を優先します。電話番号がない場合はメールアドレスと氏名で再来を照合します。同じメールでも氏名が異なれば別のお客様として扱います。メールだけの台帳に後から電話番号が加わる場合は、電話番号が他の台帳と競合しない範囲で引き継ぎます。既存の台帳同士は自動統合しません。共用メールなど連絡先だけでは本人確認にはならないため、氏名も確認してください。

台帳はメールでの検索にも対応し、最新の予約に登録されたメールを連絡先として表示します。台帳名の訂正時も従来名の照合を残し、予約時点の氏名を変更しません。メールの既存表記は通知用に保存し、照合キーは小文字化します。

既存の電話番号だけの予約・台帳は削除もメールの補完も行いません。既存予約の確認・変更・キャンセルも可能です。過去の電話予約を扱うDB内部の互換処理は残しますが、新しい管理画面/APIでは手動予約もメールが必須です。Webの旧式DB関数からメールなしで登録しようとしても拒否します。

## 確認
- メール未入力・不正メールでは確認や確定ができないこと。
- 電話を空欄にして予約でき、お客様・店舗への通知が届くこと。
- 同じメールと氏名で再予約すると、台帳の履歴が同じお客様に表示されること。
- 同じメールでも氏名の違う家族が同じ台帳に統合されないこと。
- LINE連携・Google予定による受付停止・予約変更・キャンセルが継続して動くこと。
