# 前日リマインド・電話連絡

## 利用開始

1. Supabase SQL Editorの新しいクエリに `supabase/migrations/0017_booking_reminders.sql` 全文を貼り、Run。0016まで適用済みのDBが対象です。
2. Vercelのプロジェクト → Settings → Environment Variables → Productionに `CRON_SECRET` を追加。パスワード管理アプリ等で生成した32文字以上のランダムな秘密文字列を使用します。Macのターミナルなら `openssl rand -hex 32` で生成できます。チャットやGitHubに貼らないでください。
3. 再デプロイしてReadyを待ち、管理画面 →「前日連絡」→「前日通知を有効にする」。初期設定は停止です。店舗ごとに有効化します。
4. LINE連携済みの翌日予約で「未送信の前日通知を送信・再送」を押して、届く日時・担当者を確認します。テストにも実際の通知が送られます。キャンセルや担当者変更後は古い未送信通知が無効になります。
5. Vercel Settings → Cron Jobsで `/api/cron/reminders` を確認。UTC `0 0 * * *` は日本時間午前9時です。Hobbyは指定時刻から最大約1時間の幅があるため、9時ちょうどは保証しません。定期実行はProductionのみです。

## メール（Resend）

1. [Resend](https://resend.com/) にアカウントを作成。
2. Domainsから所有する送信元ドメインを追加し、指定されたDNSレコードで認証します。他店舗でも利用する共通サービスの送信元ドメインとして使用します。メール本文に店舗名を記載します。
3. API Keysでメール送信可能なキーを発行。
4. Vercel Productionに `RESEND_API_KEY` と `REMINDER_EMAIL_FROM`（例：`予約のお知らせ <booking@自分の認証済みドメイン>`）を登録。例の値はそのまま使わず、認証済みの実在アドレスを指定します。
5. 再デプロイし「前日連絡」のメール未設定表示が消えることを確認。LINE未連携かつメール登録ありの新しい翌日予約でテスト送信します。Resendのテスト送信元は制限があるため、本番では認証済みドメインが必要です。

送信先の優先順位はLINE → メール → 電話です。両方登録していても自動通知は一方のみ。配信サービス未設定ならメール登録者も電話対象です。すでに作成された電話対象はメール設定後も電話対応のままです。初めてメール設定する場合は、店舗を有効化する前に設定を済ませると確実です。予約時のメール入力・LINE連携は任意です。SMSは使用しません。

## 店舗の運用

「前日連絡」に送信待ち・配信サービス受付済み・送信失敗・電話対象・電話連絡済みを表示します。配信受付は受信・既読を保証しません。メール不達やブロックは配信サービスの管理画面でも確認してください。電話で本人に伝えた後に「電話で連絡済みにする」を押します。不在・留守電なら対象を残します。担当者ID・記録時刻を保存します。

一回の送信は最大40件、処理時間約40秒まで。残りは管理画面から続けて送信してください。メールは控えめな送信間隔を空けます。配信サービスの契約やアカウントの制限も適用されます。停止中の店舗は自動・手動とも送信されません。日次Cronだけでは日中の再送や前日9時以降に入った予約に対応しないため、営業時間中に管理画面を確認して未送信を送信してください。通知失敗の再試行は約2分後から可能です。

同時実行はDBの2分リースで同一通知を取り合わないようにし、再送は同じUUIDをLINE retry key / Resend idempotency keyとして利用します。受け付け済みのDB記録が失敗した場合にも重複を抑えます。23時間を過ぎた未確定通知は電話確認の対象にして、プロバイダの24時間の重複防止期限を超える自動再送を避けます。送信開始後に予約や設定が変わった場合、すでに配信サービスが受け付けた通知は撤回できません。

明日の予約が対象で、予約開始後には連絡対象から除外します。最大200件を画面に表示します。大規模な店舗数・件数に拡張する場合は、より頻繁な定期処理と一覧ページ送りが必要です。

## 個人情報・通知本文

通知本文は店舗・予約日時（日本時間）・施術・担当者のみ。電話番号、メールアドレス、施術メモは含めません。既存の予約専用リンクを再発行せず、保存したリンクからの確認を案内します。メールだけで予約した方は予約完了画面でリンクを保存してください。

連絡先は店舗で認証した管理画面に限って表示し、通知ジョブのDBテーブルはRLSとサービス専用RPCで制限します。Cronは32文字以上の `CRON_SECRET` を検証し、個人情報や鍵をレスポンス・ログへ出しません。LINEの設定・認証情報は既存の店舗別暗号化設定を使用します。

参照: [Vercel Cronの制限](https://vercel.com/docs/cron-jobs/usage-and-pricing)、[Resend API](https://resend.com/docs/api-reference/introduction)、[Resendの再送キー](https://resend.com/docs/dashboard/emails/idempotency-keys)。
