# Googleカレンダー連携の準備（店舗共通カレンダー）

0024_google_calendar.sqlをSupabase SQL Editorで全文実行してください。0023まで適用済みであることが前提です。連携コードは用意済みですが、Google側の設定と店舗による接続が必要です。

## 1. 予約専用カレンダーを作る
パソコンで https://calendar.google.com/ を開きます。「他のカレンダー」の＋ →「新しいカレンダーを作成」で、例「店舗予約」を作成します。タイムゾーンは日本時間にします。公開設定にはしません。
「設定」→そのカレンダー→「カレンダーの統合」の「カレンダーID」を後で接続時に使います。

## 2. Google Cloudプロジェクトを作る
https://console.cloud.google.com/ を開き、上部のプロジェクト選択 →「新しいプロジェクト」で予約システム用のプロジェクトを作ります。例「reserve-service」。作成後、そのプロジェクトを選択します。

## 3. Google Calendar APIを有効にする
「APIとサービス」→「ライブラリ」で「Google Calendar API」を探し、「有効にする」を押します。

## 4. Google Auth Platformを準備する
「Google Auth Platform」（画面によっては「APIとサービス → OAuth同意画面」）を開きます。開始画面に従い、アプリ名・サポートメール・連絡先メールを登録します。
外部のGoogleアカウントでも店舗ごとに接続するため、対象は通常「外部」です。検証中はテストユーザーとして、今回カレンダーを所有するGoogleアカウントを追加します。

## 5. OAuthクライアントを作成する
Google Auth Platform →「クライアント」→「クライアントを作成」で「ウェブアプリケーション」を選びます。名前は例「予約管理Web」。
「承認済みのリダイレクトURI」に次を登録します（末尾を変えずに入力します）。

`https://reserve-service-beryl.vercel.app/api/admin/calendar/callback`

別の公開ドメインを使う場合は、管理画面のGoogle連携の「接続の準備・使い方」に表示されるURLを登録してください。URLのホストはVercelの公開URL設定に一致させます。

## 6. Vercelへ登録する
Vercel → reserve-service → Settings → Environment Variablesに、Googleが発行した値を登録します。
- `GOOGLE_CALENDAR_CLIENT_ID`：クライアントID
- `GOOGLE_CALENDAR_CLIENT_SECRET`：クライアントシークレット
Productionへ保存して再デプロイします。暗号化には既存の `LINE_SETTINGS_ENCRYPTION_KEY` を使い、変更しません。秘密の値はチャットへ貼り付けないでください。

## 7. 店舗管理画面から接続する
店舗設定 → LINE・メール・前日通知の設定 → Googleカレンダー連携を開きます。予約専用カレンダーのIDを入力し、「Googleカレンダーを接続」を押します。Googleの画面でカレンダーを管理するアカウントを選び、必要な権限を許可します。
管理画面へ戻ったら、店舗設定のGoogle連携で「未反映の予定を同期」を押します。未反映が残る場合は再度実行します。今後の確定予約が登録されます。その後の予約作成・日時や担当者変更・キャンセルは操作後に自動反映し、失敗した分はこのボタンで約2分後から再試行できます。

## 運用範囲と注意
現在は「予約システム → Googleカレンダー」への反映です。予約変更・キャンセルは予約システムで行います。Google側の私用予定で空き枠を制限する機能は、その後に追加します。予定の時刻は施術開始・終了で、準備時間は予約システム側で判定します。

カレンダーへ載せるのは予約時の氏名・施術メニュー・登録済み担当者名・管理画面のリンクです。電話番号・メールアドレス・スタッフ用メモ・本人用の操作リンクは載せません。選択するカレンダーは非公開とし、必要なスタッフだけに共有します。

Google連携を解除してもGoogle側の既存予定は残ります。別カレンダーへ接続し直した場合も以前のカレンダーは自動削除しません。Googleの接続許可自体を取り消す場合は、Googleアカウントの「サードパーティのアプリとサービス」で解除します。

Googleのテスト公開状態では、要求するスコープによって認可が7日で切れます。テスト中は再接続が必要になる場合があります。本運用前にGoogle Auth Platformの公開状態、所有ドメイン、プライバシーポリシー、必要な審査を確認します。接続シークレットや暗号鍵は通常の運用で変更しないでください。
