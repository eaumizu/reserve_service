# 空き枠取得のCPU使用量

本番のWorkers Freeで、予約画面の日付を切り替えた際のCPU時間の中央値は31.22ms、朝の処理付近には約115msが観測された。ここでの改善はアプリケーションコードのCPU負荷を減らすもので、Freeの原則10ms以内を保証するものではない。

## 今回の変更

- 公開空き枠APIの1リクエスト内で、サーバー専用Supabaseクライアントを予約ルール・担当者別空き枠・Google予定確認に渡す。リクエスト間でクライアントや認証状態を共有しない。
- 外部読み取り後に受付期限と予約可能日を一度計算し、全担当者の枠を同じ現在時刻で判定する。既存予約・Google予定などの判定結果はリクエスト間でキャッシュしない。
- 15分刻みの候補計算は占有区間を一度数値に変換し、不要なDate生成と暗黙のDate変換を減らす。施術前後のバッファー、終了境界、日跨ぎの判定は維持する。
- Google終日予定の変換では、Intl.DateTimeFormatだけを最大16タイムゾーン分再利用する。予定、宛先、OAuthトークンはこのキャッシュに入れない。同じ変換器でも日付ごとの夏時間を反映する。

DBのSQL、予約確定処理、Googleの権限、通知先・通知タイミング、契約プランは変更しない。DB/Googleへの問い合わせ回数を減らすキャッシュは今回導入していない。

## 再現用ベンチマーク

`benchmarks/availability.cjs`は、実際の公開空き枠APIとSupabase SDKを、固定したテスト応答で呼ぶ。fetchはすべて差し替え、未知の宛先はエラーにする。本番DB・Google・メール・LINEへ通信しない。実行時の環境変数はテスト値で上書きする。

```sh
# app/ と lib/ の変更前スナップショットを空の一時ディレクトリへ展開する。
mkdir -p /tmp/availability-before
git archive <変更前コミット> app lib > /tmp/availability-before.tar
tar -xf /tmp/availability-before.tar -C /tmp/availability-before

node benchmarks/availability.cjs --source /tmp/availability-before
node benchmarks/availability.cjs
```

同じマシン・Nodeバージョンで交互に3回ずつ実行した。各シナリオ20回のウォームアップ後に100回計測し、1回あたりプロセスCPU時間の3実行の中央値を比較した。変更前はリモートmainの`0b0ee428a13cf2b59fc27c3fdcf48ca64eb361fb`と同じソース。

| テスト条件 | 変更前CPU | 変更後CPU | 削減 | 通信回数（前後同じ） |
| --- | ---: | ---: | ---: | ---: |
| 担当者1人・時間指定のGoogle予定 | 2.677ms | 2.061ms | 23.0% | 14回 |
| 担当者3人・時間指定のGoogle予定 | 2.899ms | 2.030ms | 30.0% | 26回 |
| 担当者1人・Google終日予定20件 | 4.671ms | 1.928ms | 58.7% | 14回 |

前後でレスポンスの予約枠のハッシュが一致することも確認した。この数値はNode上でのアプリケーションコードの比較であり、Next/OpenNextサーバー処理、起動直後の読み込み、実際のWorkers環境は含まない。本番の31.22msが同じ比率で下がるとは扱わない。

## 反映後の確認

1. 予約用WorkerのDeploymentsで、この変更を含むmainのデプロイ成功を確認する。
2. 同じメニューで日付を2〜3回切り替え、空き枠とエラーの有無を確認する。
3. Metricsの対象を変更後のバージョンにし、同程度のリクエストが集まってからCPU・Invocation Statusesを比較する。実行がない時間帯の0msを軽量化の結果として扱わない。
4. 空き枠の鮮度を落としたりGoogleの受付停止判定を解除したりせず、FreeのCPU上限に十分な余裕があるか判断する。Paidへ変更する場合も同じ改善を利用できる。

回帰確認には、既存の予約・変更・バッファー・Google busyテストに加え、日跨ぎを含む多数の占有区間、受付締切をまたぐ外部読み取り、夏時間の切り替わりを含む終日予定を使用する。Workersのネイティブ実行テストでも、再利用したタイムゾーン変換器の冬・夏の結果を確認する。
