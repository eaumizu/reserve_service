# 店舗への予約メール通知

## 設定
1. Supabase SQL Editorで `supabase/migrations/0023_store_booking_notifications.sql` の全文を実行します。0022まで適用済みであることが前提です。
2. 管理画面 → 店舗設定 → LINE・メール・前日通知の設定 → 店舗向け予約通知を開きます。
3. 店舗スタッフが受信できるメールアドレスを入力し、「店舗への予約通知を有効にする」を選んで保存します。
4. 既存の店舗メール送信元が認証済みで、Vercel ProductionにRESEND_API_KEYが登録済みなら、送信元を再登録する必要はありません。
5. 新しいテスト予約を登録し、店舗向けメールを受信できることを確認します。日時・担当者変更とキャンセルでも確認します。

## 通知内容
新規Web予約、電話・店頭・管理画面の新規予約、日時・担当者変更、キャンセルを店舗へ通知します。お客様のLINE連携やメール入力の有無には依存しません。施術完了・無断キャンセル・メモの編集では送信しません。設定前の古い予約を有効化だけで一斉送信することはありません。

メールには予約時の氏名、電話番号、日本時間の予約日時、メニュー、担当者名（登録されている場合）、管理画面のリンクを載せます。スタッフ用メモや、お客様本人用の操作リンクは含めません。予約確認には管理画面でログインします。

## 失敗した場合
予約は保存済みのままです。連絡管理に店舗向けメールの未送信件数を表示します。店舗設定の「店舗向け通知の状況を見る」で直近20件の状態を確認し、未送信を再送します。約2分の再送待ち時間、排他的な送信処理、同じ通知IDによる重複防止があります。23時間を過ぎた通知や受信先・送信元設定を変更した古い通知は再送せず、予約一覧で確認してください。設定変更の前に送信処理を開始した通知は、以前の設定で届く場合があります。

配信受付済みはResendが受け付けた状態で、受信箱への到達や既読を保証しません。通知先の保存と再送は管理者のみ操作できます。

## 未送信が続くとき
「店舗向けの未送信メールを再送」を押した結果に、送信元未認証・送信元設定の変更・配信権限・送信制限などの理由を表示します。画面を開いたり更新しただけでは再送しません。失敗から2分以内は再送対象にならないため、2分以上待って操作してください。

Resendの一時的な429応答は、同じ通知IDを維持して最大2回再試行します。共有ワーカー内で送信を順番待ちし、各通信の6秒タイムアウトは順番が来てから開始します。別のワーカーによる送信や配信サービスの上限があるため、必ず届くことを保証するものではありません。回復しなかった通知は未送信のまま保持し、手動再送が必要です。日次の前日リマインドとは別の処理で、店舗通知を翌朝まで待たせる仕様ではありません。

Vercelログには `store_booking_notification_failed` と通知ID・限定したエラー区分を記録します。APIキー、送信先、予約本文、配信サービスの応答本文は記録しません。本番の原因を確認できない場合は、画面の再送結果またはResend Logsのエラー種別を確認してください。
